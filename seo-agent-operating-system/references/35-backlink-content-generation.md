# Backlink Content Generation

## Purpose

Create proposed content for an approved backlink opportunity using property context, target/anchor planning, publisher requirements, and the exact activity workflow.

The output is proposed content for human review unless the platform explicitly allows automatic publishing.

## Inputs

Load:

- [04-property-context.md](04-property-context.md)
- [33-backlink-activity-classification.md](33-backlink-activity-classification.md)
- [34-backlink-target-anchor.md](34-backlink-target-anchor.md)
- [36-publisher-guidelines.md](36-publisher-guidelines.md) when site-specific rules exist
- The exact activity file from [59-offpage-activity-map.md](59-offpage-activity-map.md) when the content belongs to a defined off-page activity

## Content types

Generate only the type required by the activity file and publisher/platform rules:

- Guest post or guest blog
- Contributor/article submission
- Micro-blog post
- Profile/about text
- Resource/directory description
- Forum/Q&A contribution
- Blog comment when appropriate
- PPT/PDF/video supporting metadata
- Press release copy
- Outreach pitch copy
- Link-insertion suggestion

## Content requirements

Use only supported client facts.

Align with:

- Client audience
- Client positioning
- Topic relevance
- Target page
- Planned anchor
- Activity purpose
- Publisher/platform tone and format
- Word-count or formatting rule when explicitly provided
- Author/signature context when required

## Guardrails

- Do not invent client claims, awards, statistics, credentials, or case studies.
- Do not force an anchor where it reads unnaturally.
- Do not reuse one generic article across unrelated publishers.
- Do not ignore publisher restrictions.
- Do not assume generated content must be used unchanged.
- Do not create generic spam comments/replies for link volume.

## Quality checks

Before output verify:

- Topic fits publisher/platform and client
- Link fits context
- Client facts are supported
- No conflicting property context
- No duplicate/recycled sections when originality is required
- CTA is appropriate for the activity
- Author/signature information is correct

## Output

Return proposed title/topic, content, target URL, anchor/placement, author/signature if required, activity/publisher rules applied, missing information, and human review status.

## Handoff

Send approved content to the exact activity workflow and [37-backlink-outreach-submission.md](37-backlink-outreach-submission.md) when shared submission/outreach mechanics are needed.

Send content-quality feedback separately to [39-backlink-feedback-learning.md](39-backlink-feedback-learning.md).
