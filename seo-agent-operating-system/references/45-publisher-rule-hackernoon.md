# Publisher Rule Record - HackerNoon

## Purpose

Provide a real example of a publisher-specific record using current public HackerNoon guidance.

This is not a permanent rule. Revalidate before every planned campaign because publisher policies change.

## Record metadata

- Domain: `hackernoon.com`
- Publisher: HackerNoon
- Primary niche: Technology/startups/software/engineering and adjacent tech topics
- Last public verification: 2026-09-17
- Status: `NEEDS_REVALIDATION_BEFORE_SUBMISSION`

## Current public process

HackerNoon currently states that writers can submit stories, but publication is not guaranteed. Stories go through editorial review.

A typical submission path is:

1. Log in.
2. Start writing/create a story.
3. Add title, feature image and suitable tags.
4. Complete story settings.
5. Submit for editorial review.

## Content fit

Prefer:

- Real technology experience
- Original analysis/point of view
- First-person practitioner perspective where appropriate
- Useful sources/research
- Readable formatting with headings/lists

Avoid topics/content positioned mainly as backlink spam or generic local-service SEO promotion.

## Brand identity

For brand publishing, HackerNoon's current brand rules require a complete brand profile and official brand email. Revalidate the exact current program/pricing before execution.

## Backlink guidance

Public HackerNoon help pages currently agree on these principles:

- Promotional/brand links must be limited.
- External source diversity is expected.
- Link relevant HackerNoon stories and reputable outside sources.
- Spammy/promotional anchor text and sketchy sites are not allowed.
- Adding promotional links after publication can trigger enforcement.

## Current public rule conflict

Two current HackerNoon help pages expose different promotional-link ratios:

- Backlinks guideline page: about 1 brand/personal promotional link per 500 words.
- Editing-protocol backlink-limit page: about 1 brand/personal promotional link per 300 words.

Do not silently choose one as authoritative. Mark `PUBLIC_RULE_CONFLICT` and re-check the live editor/submission guidance before drafting the final link plan.

If the conflict cannot be resolved, use the stricter limit for draft safety and request editorial confirmation.

## Republishing

HackerNoon currently provides a `First seen at`/canonical workflow for eligible republished content. Verify eligibility for the specific writer/brand account.

## Stop conditions

Do not submit when:

- Topic is not a real fit for the publication.
- Content exists mainly to place links.
- Client identity/brand account requirement is not satisfied.
- Link limits/anchor policy remain unresolved.
- Article contains unsupported or spammy promotional claims.
