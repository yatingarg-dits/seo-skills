# Off-Page SEO Activity Map

## Purpose

Route each off-page activity to its own process file. Use this map after the activity is identified.

The supplied activity list contains both backlink-building activities and broader off-page/indexing/distribution activities. Do not force every activity through the same execution path.

## Common prerequisites

Before executing any activity, load as applicable:

- [01-platform-seo-context.md](01-platform-seo-context.md)
- [02-agency-seo-overrides.md](02-agency-seo-overrides.md)
- [03-client-context.md](03-client-context.md)
- [04-property-context.md](04-property-context.md)

For external websites that create or may create a backlink, normally use:

`30-backlink-discovery` -> `32-backlink-qualification` -> `33-backlink-activity-classification` -> activity file -> `38-backlink-verification-monitoring` -> `39-backlink-feedback-learning`

For community-sourced opportunities, add [31-community-link-intake.md](31-community-link-intake.md) before qualification.

## Overlap rules

- **Link Building** is the overall acquisition strategy. **Backlinks** is the link-level execution/result record.
- **Guest Posting** and **Guest Blogging** are separate source labels but share qualification/publisher controls unless the team defines a difference.
- **Forums** and **Forum Participation** are separate source labels but share platform/profile/moderation/relevance controls unless the team defines a difference.
- **Business Listing** remains separate from backlink execution even when a listing creates a link.
- **Search Engine Submission** and **Ping Submission** are indexing/discovery activities, not backlink-quality activities.

## Global guardrails

- Do not mass-post solely to manufacture links.
- Follow platform/editorial rules.
- Use client-approved identity, descriptions, URLs, anchors, media, and contact data.
- Do not invent credentials, company facts, author identity, or contact details.
- Do not treat a created link as successful until verified.
- Record free/paid/registration/outreach status and failure reason.
- Use `NEEDS_HUMAN_RULE` when team-specific volume, threshold, platform list, or approval rule is missing.
