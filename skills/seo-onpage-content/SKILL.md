# SEO On-Page and Content

## Mission

Make every important page clear, useful, trustworthy, aligned with search intent, connected to business goals, and safe to publish. Optimize for users first while making the page easy for search engines and AI systems to understand.

Use this flow:

**Understand page purpose -> validate intent -> inspect current performance -> research topic and competitors -> improve content and on-page elements -> connect internal links and conversion path -> QA -> approve when needed -> publish -> verify -> measure.**

## Required Inputs

Use or request:

- URL or proposed page type.
- Business goal and conversion goal.
- Target audience.
- Primary geography/language.
- Primary topic and related topics.
- Current rankings, Search Console, analytics, and conversion data when available.
- Existing page content and structure.
- Competitor/SERP evidence.
- Brand guidelines.
- Legal/compliance restrictions.
- Approval workflow.

If performance data is missing, do not assume the page is weak only because an SEO tool reports issues.

## 1. Page Purpose

Every page should have one clear main purpose.

Examples:

- Product discovery.
- Category discovery.
- Service conversion.
- Local conversion.
- Informational education.
- Comparison/consideration.
- Pricing/demo/booking.
- Support or documentation.

A page may rank for many related terms but should not try to serve unrelated intents.

## 2. Search Intent

Before optimization:

- Identify what the user is trying to accomplish.
- Confirm the dominant SERP page type.
- Check whether the current page format matches that intent.
- Check whether the page is commercial, informational, comparison, transactional, navigational, or local.

Do not try to fix an intent mismatch by adding more keywords.

## 3. Existing-Page Protection

Before major edits, check:

- Rankings.
- Impressions.
- Clicks.
- CTR.
- Organic traffic.
- Leads/sales/revenue.
- Backlinks.
- Current keyword footprint.

If the page is already performing strongly, prefer small, measurable changes over full rewrites.

## 4. Title Tag

Create or improve the title so it:

- Accurately describes the page.
- Matches the main topic and intent.
- Uses the primary concept naturally.
- Gives a compelling reason to click when appropriate.
- Differentiates the page from similar pages.
- Reflects geography when location matters.
- Includes brand naming where useful.
- Avoids repetitive keyword stuffing.

Treat length limits as display heuristics, not ranking laws. Do not change a successful title only to satisfy a character-count rule.

## 5. Meta Description

Write a description that:

- Accurately summarizes the page.
- Communicates value.
- Matches user intent.
- Uses natural language.
- Includes an appropriate action or benefit where useful.
- Avoids claims the business cannot support.

Do not treat meta descriptions as guaranteed snippets or direct ranking factors.

## 6. H1 and Heading Structure

Use:

- One clear main H1 in normal cases.
- H2s for major sections.
- H3s and deeper levels for logical subsections.

Headings should organize information, not exist only to insert keywords.

Do not use heading levels purely for visual styling.

## 7. URL Rules

Prefer URLs that are:

- Clear.
- Readable.
- Stable.
- Descriptive enough to understand the page.
- Free of unnecessary parameters when a clean canonical URL is intended.

Do not change an existing URL without a strong reason and approval. URL changes require redirect planning and technical review.

## 8. Main Content Quality

Assess whether the page:

- Answers the user's real need.
- Is accurate.
- Is complete enough for the topic.
- Is easy to understand.
- Adds original value.
- Avoids unnecessary repetition.
- Uses examples where useful.
- Uses evidence for factual or high-risk claims.
- Helps the user make a decision or complete a task.
- Connects logically to the intended conversion.

Do not optimize for a target word count. Add content only when it improves usefulness.

## 9. Topic and Semantic Coverage

Cover the concepts naturally associated with the topic.

Use related terms, entities, questions, subtopics, attributes, use cases, and decision factors when they genuinely improve the page.

Do not force every semantic variation into the copy.

## 10. Content Research

Before creating or substantially refreshing content:

- Review target-market SERPs.
- Identify dominant search intent.
- Review leading competitor pages.
- Identify recurring subtopics and questions.
- Identify what competitors omit.
- Find reliable sources for important facts.
- Gather client-specific evidence, examples, case studies, product facts, and expert input.
- Identify internal pages that should be linked.
- Identify conversion paths and CTAs.

Separate competitor inspiration from copying.

## 11. Content Brief

A production-ready brief should include:

- Business objective.
- Page objective.
- Audience.
- Search intent.
- Primary topic.
- Supporting topics.
- Proposed page type.
- Suggested heading structure.
- Questions to answer.
- Important entities/concepts.
- Competitor insights.
- Content gaps.
- Required evidence and sources.
- Internal links to include.
- External source requirements.
- CTA and conversion goal.
- Brand requirements.
- Restricted claims.
- Expert/legal/compliance review needs.
- Pre-publish QA items.

Do not create briefs from keywords and word count alone.

## 12. Content Creation

When drafting content:

- Answer the main need early.
- Use clear language suitable for the audience.
- Write in the brand voice.
- Use primary and related concepts naturally.
- Add practical examples, comparisons, steps, evidence, or first-hand insight where possible.
- Keep claims specific and supportable.
- Avoid filler written only to increase length.
- Avoid copying competitor phrasing.
- Avoid unsupported superlatives and guarantees.
- Include a useful next step when a conversion is appropriate.

## 13. E-E-A-T and Trust

Check for appropriate evidence of experience, expertise, authoritativeness, and trustworthiness, especially in high-risk topics.

Possible trust signals:

- Named author.
- Relevant author qualifications.
- Expert review.
- Clear company information.
- Accurate contact details.
- Methodology.
- First-hand examples.
- Original research.
- Primary-source citations.
- Updated dates where facts change.
- Clear disclosures.
- Policies and support information.

Do not invent expertise, authors, research, certifications, customer outcomes, or statistics.

## 14. High-Risk Content

For healthcare, finance, legal, insurance, safety, or other consequential topics:

- Require stronger evidence.
- Use current authoritative sources.
- Flag jurisdiction-specific facts.
- Avoid personalized professional advice unless appropriately authorized.
- Require subject-matter or compliance review when needed.
- Do not publish strong claims solely because competitors make them.

## 15. Claims and Evidence

For factual claims:

- Prefer primary or authoritative sources.
- Verify dates.
- Verify units, rates, prices, percentages, and regulatory statements.
- Record source URLs or internal evidence where the workflow supports it.
- Distinguish measured client results from general claims.

Never create a statistic to make content look more authoritative.

## 16. Original Value

Improve content beyond generic summaries with useful additions such as:

- First-hand experience.
- Original examples.
- Expert commentary.
- Proprietary data.
- Case studies.
- Process explanations.
- Decision tables.
- Checklists.
- Calculators/tools.
- Visual demonstrations.
- Common mistakes.
- Practical trade-offs.

Do not add features only because competitors have them.

## 17. Internal Linking

For every important page, check:

- Relevant incoming internal links.
- Relevant outgoing internal links.
- Orphan-page status.
- Click depth.
- Link placement in useful context.
- Anchor text naturalness.
- Whether priority commercial pages receive enough internal support.

Use anchors that describe the destination naturally. Avoid repeated exact-match anchors across the site.

## 18. External Linking

Link externally when it improves user understanding or supports evidence.

Prefer:

- Official sources.
- Government sites.
- Universities.
- Recognized research organizations.
- Primary documentation.
- Trusted industry bodies.

Do not link to poor-quality pages merely because they contain a target keyword.

## 19. Image SEO

For meaningful images:

- Use relevant visuals.
- Compress without unacceptable quality loss.
- Use appropriate modern formats when supported.
- Use descriptive filenames when practical.
- Add meaningful alt text for informative images.
- Keep decorative images from receiving misleading alt text.
- Define useful dimensions to reduce layout shifts.
- Ensure important text is not available only inside an image.

Alt text should describe the image, not repeat keywords unnaturally.

## 20. Product Pages

Check:

- Accurate product name.
- Unique and useful product information.
- Price.
- Availability.
- Specifications.
- Images/video.
- Reviews where legitimate.
- Shipping/returns.
- FAQs when useful.
- Related products.
- Clear CTA.
- Product schema alignment with visible data.

Do not create separate indexable variant pages unless each has unique value and real search demand.

## 21. Category Pages

Check:

- Clear category purpose.
- Useful title/H1.
- Relevant product/service listings.
- Helpful filtering.
- Introductory or buying guidance only when useful.
- Internal links.
- Conversion support.
- Indexation strategy for filters.

Do not add large blocks of generic SEO copy solely to increase word count.

## 22. Service Pages

Check:

- Clear service definition.
- Who the service is for.
- Problems solved.
- Process.
- Deliverables.
- Proof/trust signals.
- Pricing or qualification guidance where appropriate.
- Geography/service area where relevant.
- FAQs.
- CTA and conversion path.

## 23. Comparison and Review Content

For comparison/review pages:

- Explain evaluation criteria.
- Use current product/service facts.
- Disclose commercial relationships where required.
- Add first-hand experience where possible.
- Explain who each option suits.
- Include meaningful pros/cons.
- Avoid fake experience or fabricated testing.

## 24. FAQ Content

Use FAQs only when they address real user questions.

Do not create repetitive FAQ blocks merely to target long-tail keywords or schema opportunities.

## 25. Content Refresh

Refresh based on evidence such as:

- Ranking decline.
- Impression decline.
- CTR decline.
- Conversion decline.
- Outdated facts.
- Intent shift.
- Competitor improvement.
- Missing information.
- Product/service changes.

Do not rewrite content merely because it is old.

## 26. Content Decay

For declining pages, compare:

- Current vs historical clicks/impressions/rankings.
- Query mix.
- SERP layout.
- Search demand.
- Competitor changes.
- Content freshness.
- Internal links.
- Backlinks.
- Conversion performance.

Diagnose before rewriting.

## 27. Cannibalization

When multiple pages target similar terms:

- Compare search intent.
- Compare ranking queries.
- Check which page Google prefers.
- Check business purpose.
- Check conversion value.

Possible actions:

- Keep both if intent differs.
- Differentiate.
- Merge.
- Reposition.
- Redirect with approval when consolidation is justified.

## 28. AI-Assisted Content at Scale

When AI is used:

- Verify accuracy.
- Remove hallucinations.
- Add original value.
- Check duplication/repetition.
- Enforce brand rules.
- Review sensitive claims.
- Avoid publishing hundreds or thousands of low-value pages merely because keywords exist.
- Increase QA and approval rigor as scale grows.

AI use itself is not the quality test. Usefulness, accuracy, originality, and governance are.

## 29. Conversion Alignment

SEO content should support the correct business action.

Check:

- CTA relevance.
- CTA visibility.
- Friction in forms/checkout/booking.
- Alignment between keyword intent and CTA.
- Whether the page attracts the right audience.

If a page ranks well but does not convert, investigate intent, audience fit, offer, CTA, trust, and user experience before calling SEO successful.

## 30. Pre-Publish SEO QA

Before publishing, verify:

- Correct topic and intent.
- Title.
- Meta description.
- H1/headings.
- URL.
- Main content quality.
- Brand voice.
- Claims and evidence.
- Internal links.
- External citations.
- Images and alt text.
- CTA.
- Duplicate/cannibalization risk.
- Canonical intent.
- Indexability intent.
- Schema requirements.
- Expert/compliance approval.
- Tracking requirements.

## 31. Post-Publish Verification

After publishing, verify the live page:

- Loads successfully.
- Uses the intended URL.
- Shows the correct title/meta/H1.
- Has the intended canonical.
- Has the intended indexability state.
- Contains working internal/external links.
- Renders key content on mobile.
- Exposes structured data correctly where used.
- Fires analytics/conversion tracking as expected.

Do not assume implementation is correct because the CMS shows the right draft.

## 32. Measurement

Measure the KPI appropriate to the page:

- Rankings.
- Impressions.
- Clicks.
- CTR.
- Organic sessions.
- Engagement where useful.
- Leads.
- Purchases.
- Revenue.
- Bookings.
- Assisted conversions.

Keep a before/after record for meaningful changes.

## Non-Negotiable Rules

- Never stuff keywords.
- Never optimize to a fixed keyword density.
- Never increase word count without a user need.
- Never invent facts, reviews, statistics, expertise, or client results.
- Never rewrite a strong-performing page without evidence and appropriate approval.
- Never create a new page without checking whether an existing page can serve the intent.
- Never publish regulated or high-risk claims without the required evidence/review.
- Never assume AI-generated content is correct.
- Never treat publishing as completion; verify the live implementation and measure performance.
